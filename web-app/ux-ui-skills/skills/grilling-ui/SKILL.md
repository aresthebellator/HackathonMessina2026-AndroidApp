## Doctrine

**Grill, don't glance. "Looks mostly fine" is not an audit; it is the absence of one.** This is the Matt Pocock grill-with-docs bar pointed at existing UI: relentless, specific, evidence-demanding interrogation, never surface-level acceptance. The default posture is not "find the obvious problems" — it is *every surface is guilty until a specific principle clears it*. A reviewer who scans a screen and says "this is pretty good" has not audited it; they have looked at it. Looking is the failure mode this skill exists to kill. You interrogate each element until it either fails against a named standard or is explicitly cleared against one — there is no "seems okay so I moved on". "Nothing major jumped out" is itself the defect: it means you stopped at the glance.

**Every finding is anchored, or it is not a finding.** A finding is delivered only when it carries one of exactly two anchors: (a) a specific named principle — cite the exact `design-judgment-references` reference file *and* the principle within it (e.g. `nielsen-heuristics.md` H8 for clutter, H4 for one thing rendered three ways, H1 for missing system status), not "Nielsen says so"; or (b) a concrete brief or token violation — quote the offending brief line, or name the token the value should be and the raw value it is instead. "Feels cluttered", "looks dated", "could be cleaner", "not professional" are *symptoms*, not findings. **Presence of a citation is not anchoring; fit is.** An anchor that names a real principle which does not actually govern the quoted element is the SAME failure as no anchor — a real file loosely bolted onto a taste reaction ("looks dated → `rauno-craft.md` missing states") is decorative anchoring: taste with a footnote, the unanchored failure wearing a file name. Every finding must therefore state, in one line, WHY this specific principle condemns this specific quoted element; if that why-line cannot be written, the principle does not fit and the finding is unanchored. An unanchored symptom is discarded **from the findings and recorded in the report as an explicit discard with its reason, never silently dropped** — and shipping one anyway is itself the failure this skill is graded on, exactly as `design-judgment-references` says: an unanchored finding from this skill is a process defect in *this* run, not a stylistic preference of the reviewer. The anchor is not decoration on the finding; it *is* the finding.

**Ranked, never flat. Blocking / Should / Consider.** A flat list of problems hides the only thing the reader needs: what stops the ship. Every finding lands in exactly one tier. **Blocking** — ships broken, materially violates the brief, or materially fails a heuristic (the user cannot complete the job, or the defect is plainly wrong, not arguable). **Should** — a real, anchored defect that is not ship-blocking (it should be fixed; the ship survives without it). **Consider** — a defensible judgment call where a named principle still applies but reasonable craft could land either way. If you cannot place a finding in a tier, you have not understood its severity yet — that is interrogation you skipped, not a reason to flatten the list.

**Every finding carries its fix. A finding without a fix is a complaint.** "Improve the hierarchy", "make this cleaner", "this needs work" are not fixes — they hand the problem back unsolved. The fix is the specific change: the token to swap in, the element to delete, the state to add, the copy to rewrite. If you can name the principle it violates but cannot say what change satisfies that principle, you have done half the work and the finding is not done.

**Gate position and composition are fixed.** This skill requires `grounding-before-designing` to have already run: you cannot grill a surface against a system you have not grounded in — without the verified vocabulary, tokens, and brief you would be auditing against training-data fiction, and "this should be a token" is empty if you never read the real token file. It uses `anti-slop-audit` as the slop sub-routine — run that checklist as part of the interrogation, do not reinvent it. It anchors every judgment via `design-judgment-references`, and abides by that skill's rule that an unanchored finding from here is pushed back, not delivered. Run grounding first, every time, then grill.

## Process

1. **Confirm grounding is done.** Verify `grounding-before-designing` has run and a verified-vocabulary list (real components, real tokens, real data shapes) plus the filled brief exist for the surface under audit. If not, stop and run it — without it you are grilling against fiction and "use the token" has no token to name.
2. **Run the clear-attempt loop on every surface.** Go element by element — every panel, control, state, copy string, spacing, colour, depth cue. For each element/surface, run this loop explicitly: (a) name the ONE principle (from `design-judgment-references`) or brief/token rule most likely to condemn it — the Nielsen floor, Atlassian cohesion, Linear craft, Rauno interaction, Atomic composition, a quoted brief line, or a token vs raw value; (b) attempt to clear the element against that principle in one sentence; (c) if it clears, record it as cleared-and-why; if it cannot be cleared, it is a candidate finding — carry forward the quoted element *plus* the principle *plus* the one line stating why it fails that principle. Run the `anti-slop-audit` checklist as a sub-routine inside this loop. Quote the offending element verbatim. The grill IS running this clear-attempt on every surface: skipping the clear-attempt — just eyeballing a surface and calling it fine — is exactly the glance this skill forbids. "Looks fine" is never a clearance; only a named principle that the element survives is a clearance.
3. **Anchor or discard every candidate.** For each candidate finding, attach an anchor: a named `design-judgment-references` principle (exact file + exact principle/H-number) or a concrete brief/token violation (quoted brief line, or token name vs raw value) — *and* the one-line statement of why that specific principle condemns this specific quoted element (the fit/why-line; a citation that does not fit the defect is decorative anchoring, not an anchor). If no anchor with a holding why-line survives scrutiny, **discard the candidate and record it in the report as an explicit discard with the reason** — it does not enter the findings and it is never silently dropped. No unanchored survivors.
4. **Rank into tiers.** Place every surviving finding in exactly one of Blocking / Should / Consider, using the severity definitions in Doctrine. If a finding resists tiering, interrogate its impact harder until it lands; do not flatten.
5. **Attach the concrete fix.** For each finding, write the specific change that satisfies the cited principle or removes the violation — the token to substitute, the element to cut, the state to add, the exact copy. No "improve this".
6. **Emit the ranked report.** Output the three tiers in order, each finding as: anchor (named principle or brief/token violation) → defect (quoted element) → fix. Include the discarded-candidates note so it is visible that unanchored symptoms were interrogated and dropped, not missed. A report with any unanchored survivor, any fixless finding, or no tiers has failed its own bar.

## Red flags

| Rationalisation | Reality |
|---|---|
| "It looks mostly fine, nothing major stood out." | That is a glance, not a grill. The bar is every surface guilty until a named principle clears it. "Nothing stood out" means you stopped at looking — the absence of findings is the defect, not the all-clear. |
| "This feels cluttered / looks dated / could be cleaner." | Unanchored symptom, not a finding. Name the principle — clutter is almost always `nielsen-heuristics.md` H8 — or discard it. A symptom shipped without an anchor is the exact failure this skill is graded on. |
| "I'll list the issues; they can work out the fixes." | A finding without a fix is a complaint. The fix is the specific change — the token, the deletion, the added state, the rewritten copy. Half-done is not done. |
| "I'll just give a flat list of all the problems." | Unranked findings hide what blocks the ship. Every finding goes in exactly one tier — Blocking / Should / Consider. If you can't tier it, you haven't judged its severity yet. |
| "Grounding basically ran, I can grill from what I remember of the system." | "From memory" means you are auditing against training-data fiction. "Use the token" is empty until you have read the real token file. Confirm the verified-vocabulary list exists before grilling, not after. |
| "`anti-slop-audit` overlaps with this — I'll just eyeball the slop myself." | The slop checklist is a defined sub-routine for a reason: eyeballed slop is the glance again. Run `anti-slop-audit` as part of the interrogation; do not reinvent or skip it. |
| "I cited Rauno, so it's anchored." | A citation that doesn't fit the defect is decorative anchoring — taste with a footnote. The anchor must explain why THIS element fails THIS principle; if it can't, it is the unanchored failure wearing a file name. |
| "It's clearly a bad pattern — everyone would agree, I don't need to cite anything." | Consensus is not a `references/` file. Taste dressed as agreement is still taste. Anchor it to the named principle or it does not ship as a finding. |
